# Ponytail Audit

上游的整仓过度设计审计。正文从命令取，不要凭记忆复述。

## 1. 取内容

CLI 路径与 `--root` 的取法见 `ponytail` 技能（会话里以 `PONYTAIL` 开头、含 `已就绪` 的那一行，或本文件 `../../scripts/ponytail.mjs`）。

```sh
node "<CLI>" skill ponytail-audit --root "<dataRoot>"
```

## 2. 执行

1. 先摸清仓库形态再开扫：语言、构建方式、目录分层、依赖清单（`package.json` / `go.mod` / `Cargo.toml` / `pyproject.toml` 等）。审计判据依赖这些，缺了就先补齐。
2. 按取到的正文逐条扫全仓，**按收益排序**（删掉的代码行数 × 被替代的复杂度），不要按文件顺序流水账。
3. 每条写清：位置 → 现状 → 建议 → 替代物。允许「直接删」这种答案。
4. 红线不碰：信任边界校验、防数据丢失的错误处理、安全、可访问性、硬件标定旋钮。
5. 仓库很大时先给一版覆盖主要目录的抽样结果，并**明说**哪些没扫到，不要把抽样说成全量。
6. **一次性报告，不改代码。** 用户要动手再逐条确认。
