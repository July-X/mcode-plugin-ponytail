# Ponytail Review

上游的过度设计专项评审流程。正文从命令取，不要凭记忆复述。

## 1. 取内容

CLI 路径与 `--root` 的取法见 `ponytail` 技能（会话里以 `PONYTAIL` 开头、含 `已就绪` 的那一行，或本文件 `../../scripts/ponytail.mjs`）。

```sh
node "<CLI>" skill ponytail-review --root "<dataRoot>"
```

## 2. 执行

1. 先确认评审范围：默认当前改动（`git diff` / 未提交变更），用户说「整个仓库」则转 `ponytail-audit`。
2. 按取到的正文逐条找**可删项**，每条一行：位置 → 删什么 → 替代物（标准库 / 平台原生 / 已装依赖 / 直接删）。
3. 命中红线的一律不算过度设计，不要提：信任边界校验、防数据丢失的错误处理、安全措施、可访问性、真实硬件的标定旋钮。
4. **只出报告，不动代码。** 用户要动手时先问，或转 `ponytail` 技能按阶梯改。
5. 没有可删项就直接说没有，不要为了凑数把正常代码说成冗余。
